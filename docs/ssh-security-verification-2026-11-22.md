# B3-1 SSH 인바운드 접근 범위 — 기존 확인 기록 정리

검증일: 2026-11-22. 현재 실습 구성의 **보안 그룹 이름 `b31-web-sg` / ID `sg-04bc2bb098cb7bbd1`**를 기준으로 기록합니다.

## 실제 설정으로 확인된 항목

| 규칙 | 프로토콜 / 포트 | 출처와 목적 |
|---|---|---|
| 웹 HTTP | TCP 80 | `0.0.0.0/0` — 공개 포트폴리오 접근 |
| 웹 HTTPS | TCP 443 | `0.0.0.0/0` — 공개 TLS 포트폴리오 접근 |
| 직접 SSH | TCP 22 | **특정 개인 공인 IPv4 주소 하나의 `/32`** — 외부 IP 전체 공개를 피함 |
| EC2 Instance Connect 경유 SSH | TCP 22 | **AWS EC2 Instance Connect용 관리형 접두사 목록** — AWS 웹 콘솔에서 SSH 접속하기 위한 전용 출처 |

**개인 IP 공개 주의:** 당시 개인 IP는 실제 `/32` 주소로 제한한 것을 확인했지만, 사용자 요청에 따라 **공개 GitHub 문서에는 공인 IP 전체값을 기록하지 않습니다.** 평가에 필요한 보안 관점은 `/32`가 단일 IPv4 주소만 지정한다는 사실과 SSH를 불특정 전체에 공개하지 않았다는 점입니다.

**추가 확인할 값:** 실제 인바운드 규칙의 EC2 Instance Connect **접두사 목록 ID(`pl-...`) 또는 해당 규칙에 적힌 정확한 소스 문자열**은 기존 기록에 전체 문자가 남아 있지 않아 아직 확인되지 않았습니다. 이 값을 추정해서 채워 넣지는 않습니다. 연결한 접두사 목록을 사용한 설계라는 사실과 전체 ID까지 직접 검증한 사실은 구별합니다.

## IAM 및 서버 리슨 상태와 구분

- **IAM**: `b31-learner`에게 어떤 EC2·IAM 콘솔/API 작업을 허용할지 지정합니다. `iam:ListPolicies`가 거부된 실측 결과는 [IAM 검증 문서](iam-permission-verification-2026-11-22.md)에 있습니다.
- **보안 그룹**: 특정 포트로 들어올 수 있는 **네트워크 출처**를 제한합니다. IAM 작업 권한과 별개입니다.
- **Ubuntu `ss`**: 호스트의 `0.0.0.0:22` 및 `[::]:22` **리슨 여부**를 표시합니다. 어느 외부 IP가 방화벽을 통과할 수 있는지까지 보여주는 명령이 아닙니다.
- **실제 연결 근거**: 모바일 브라우저의 EC2 Instance Connect로 Ubuntu `ubuntu` 계정에 접속했고, Nginx·Docker·TLS 검증 명령을 실행했습니다.
