# B3-1 AWS 콘솔 라우팅·서브넷 연결 실측 검증 (2026-11-22 19:29 KST)

본 문서는 사용자 제공 **AWS 서울 리전 VPC 콘솔의 실제 라우팅 테이블 상세 화면**을 기준으로 작성한 텍스트 증빙입니다. 콘솔 원본 스크린샷에는 계정 관련 요소와 휴대전화 알림 등이 포함될 수 있으므로, 공개 저장소에는 **화면 전체를 직접 올리지 않고 검증 가능한 설정값만 기록**합니다.

| 항목 | 콘솔에서 확인한 값 |
|---|---|
| 리전 | Asia Pacific (Seoul), `ap-northeast-2` |
| VPC 이름 | `b31-vpc` |
| VPC ID | `vpc-03069500f8707f0f9` |
| 라우팅 테이블 이름 | `b31-rtb-public` |

## 실제 라우팅 테이블 경로

| 목적지 CIDR | 대상 | 상태 | 의미 |
|---|---|---|---|
| `10.10.0.0/16` | `local` | **활성** | 같은 VPC 주소 범위 간 내부 통신 |
| `0.0.0.0/0` | Internet Gateway (`igw-09322346b...`) | **활성** | 내부 경로에 해당하지 않는 IPv4 트래픽을 인터넷 게이트웨이로 전달 |

> Internet Gateway ID는 모바일 콘솔 화면에서 뒷부분이 잘려 있으므로 현재 확인된 접두부까지만 적었습니다. 완전한 ID를 추정하지 않습니다.

## 라우팅과 연결을 구분해 해석

- VPC의 `10.10.0.0/16` 범위에 있는 EC2가 같은 VPC 내부 주소로 요청할 때 `local` 라우트가 적용됩니다.
- 이 라우팅 테이블은 **퍼블릭 서브넷에 명시적으로 연결**되어 있으므로, `0.0.0.0/0 → IGW` 기본 경로가 해당 서브넷의 외부 목적지 트래픽에 사용됩니다.
- EC2의 공인 IP (`43.202.56.199`, 실습 당시)와 보안 그룹 인바운드 HTTP 80/HTTPS 443 허용, 호스트 Nginx 수신 및 Docker 포트 매핑이 결합되어 브라우저에서 포트폴리오에 접속했습니다.
- 라우팅 테이블과 보안 그룹은 서로 다른 계층입니다. 라우팅이 가능해도 보안 그룹이 차단하면 외부 요청이 웹 서버까지 도달하지 못할 수 있습니다.
- **Ubuntu 내부의 `ip route` 출력** (`default via 10.10.0.1 dev ens5`)은 게스트 OS의 기본 라우팅입니다. **AWS VPC 라우팅 테이블의 `0.0.0.0/0 → IGW` 설정**과 구별해서 기록했습니다.

## 검증 범위와 향후 작업

- AWS 콘솔에서 **VPC, 라우팅 테이블, 명시적 서브넷 연결, 두 경로의 활성 상태** 확인 완료.
- 인터넷 게이트웨이가 VPC에 부착된 상태는 활성 경로와 외부 접속 결과로 뒷받침되지만, 부착 화면을 별도로 찍으면 직접 증빙을 강화할 수 있습니다.
- IAM 정책 `B31PracticePolicy`의 실제 JSON과 역할/권한 범위는 별도 확인 과제입니다.
- 서버·네트워크 자원은 사용자 요청으로 삭제 보류 중입니다.
