## 삭제 시점 결정: 평가와 증빙을 모두 충족하는 순서

과제는 실제 종료·삭제 확인까지 요구하므로, 자원 삭제도 **완료해야 할 작업**으로 남겨둡니다. 다만 삭제하면 운영 중이던 `http://43.202.56.199/`과 `https://codyssey-b31-web.duckdns.org/`의 웹사이트는 현재 서버에서 더 이상 제공되지 않습니다. **운영 확인 증빙이 필요한 검사는 종료 전에 수행**합니다.

1. GitHub README·구성도·`docker ps`·웹사이트 및 `/health` 응답·최종 IAM 증빙을 확인하고, 필요하면 EC2 Nginx 설정과 Docker 실행 명령을 파일로 백업합니다.
2. **서버가 실행 중인 상태에서 사전평가를 먼저 실시**하여 서비스 접속이 필요한 미흡 항목을 확인합니다. 재평가 횟수가 제한되어 있다면 결과에 맞춰 보완합니다.
3. 최종 제출이 실제 리소스 삭제를 요구한다면, **서버·AWS 리소스가 남아 있는 모습을 먼저 캡처**한 뒤 사용자 승인 후 단계별 삭제합니다.
4. 삭제 후 EC2 `Terminated`·잔여 EBS·과제용 IGW·서브넷·VPC·보안 그룹 및 과금 자원을 확인하고 **정리 결과를 텍스트와 화면으로 기록**합니다.
5. README와 본 체크리스트에 **삭제 전 서비스 검증**과 **삭제 후 정리 검증**을 별개 시점으로 기록합니다. 제출 후 라이브 서비스 접속이 불가능하다는 사실도 표시합니다.

**주의:** 현재 EC2와 공인 IPv4 등에서 요금이 발생할 수 있습니다. 무료 요금제 적용 여부는 계정의 Billing에서 별도로 확인해야 하며, 증빙을 위해 계속 실행해 둘수록 비용 위험이 있습니다. EC2를 `Stop`해도 EBS 등 비용이 이어질 수 있고, `Terminate` 뒤에도 잔여 자원 점검이 필요합니다.

### 안전한 정리 순서

1. 아키텍처 PNG/PDF, 외부 접속, `docker ps` 및 로그 증빙을 GitHub에 저장합니다.
2. AWS 서울 리전에서 EC2 인스턴스를 **Terminate**하고 상태를 확인합니다.
3. EBS 볼륨, Elastic IP, NAT Gateway 및 다른 별도 과금 리소스가 남았는지 확인합니다.
4. 인스턴스 참조가 사라진 보안 그룹, 서브넷 연결, 사용자 지정 라우팅 테이블을 정리합니다.
5. 인터넷 게이트웨이 연결을 해제(Detach)하고 삭제한 뒤 서브넷과 VPC를 최종 정리합니다. 실제 의존 관계에 따라 4~5 순서를 조정합니다.
6. Billing 및 리소스 목록을 확인하고, 확인 시각과 스크린샷을 기록합니다.
7. 실습 전용 IAM 사용자·정책을 정리하려면 AWS 자원 삭제가 끝난 뒤 수행합니다.

**주의:** EC2 Stop은 컴퓨트 실행 요금을 멈추는 데 도움이 되지만 EBS 등 일부 리소스 비용은 계속 발생할 수 있습니다. Terminate도 잔여 볼륨이나 다른 자원의 자동 삭제를 보장하지 않으므로 별도 확인합니다. 현재 공인 IP는 자동 할당 주소로, 재시작 시 변경될 수 있습니다.
