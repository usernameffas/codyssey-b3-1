# B3-1 AWS 리소스 정리 체크리스트

**상태: 사용자 요청에 따라 삭제·중지 보류. 서버와 네트워크는 유지합니다.**

필수 과제에는 실습 종료 후 리소스 정리와 종료·삭제 완료 근거가 필요합니다. 제출용 스크린샷, `docker ps`, HTTP 및 HTTPS 접속 증빙을 먼저 확보한 다음 **사용자가 삭제를 승인한 시점**에만 정리합니다. **EC2 종료(Terminate)는 서버 내부 데이터와 실행 환경을 잃게 하는 작업**이므로 순서를 지킵니다.

| 확인 | 항목 | 현재 상태 및 완료 기준 |
| --- | --- | --- |
| ☐ | EC2 인스턴스 `b31-web` (`i-07336ff478ba4ef67`) | **미완료** · 종료 후 `Terminated` 확인 |
| ☐ | EBS gp3 8 GiB | **미완료** · 인스턴스 삭제 후 남은 볼륨 확인, 미사용 볼륨 삭제 |
| ☐ | Elastic IP | 별도 할당 기록 없음 · 실제 할당 목록에서 확인 후 있다면 Release |

| ☐ | 보안 그룹 `b31-web-sg` | **미완료** · 인스턴스와의 의존 관계 해제 후 삭제 |
| ☐ | 라우팅 테이블 `b31-rtb-public` | **미완료** · 서브넷 연결 해제 및 삭제 |
| ☐ | 퍼블릭 서브넷 `b31-subnet-public1-ap-northeast-2a` | **미완료** · 의존 리소스 제거 후 삭제 |

### 안전한 정리 순서

1. 아키텍처 PNG/PDF, 외부 접속, `docker ps` 및 로그 증빙을 GitHub에 저장합니다.
2. AWS 서울 리전에서 EC2 인스턴스를 **Terminate**하고 상태를 확인합니다.
3. EBS 볼륨, Elastic IP, NAT Gateway 및 다른 별도 과금 리소스가 남았는지 확인합니다.
4. 인스턴스 참조가 사라진 보안 그룹, 서브넷 연결, 사용자 지정 라우팅 테이블을 정리합니다.
5. 인터넷 게이트웨이 연결을 해제(Detach)하고 삭제한 뒤 서브넷과 VPC를 최종 정리합니다. 실제 의존 관계에 따라 4~5 순서를 조정합니다.
6. Billing 및 리소스 목록을 확인하고, 확인 시각과 스크린샷을 기록합니다.
7. 실습 전용 IAM 사용자·정책을 정리하려면 AWS 자원 삭제가 끝난 뒤 수행합니다.

**주의:** EC2 Stop은 컴퓨트 실행 요금을 멈추는 데 도움이 되지만 EBS 등 일부 리소스 비용은 계속 발생할 수 있습니다. Terminate도 잔여 볼륨이나 다른 자원의 자동 삭제를 보장하지 않으므로 별도 확인합니다. 현재 공인 IP는 자동 할당 주소로, 재시작 시 변경될 수 있습니다.
